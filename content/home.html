TU EINDHOVEN · 2025–2026

Restaurant Digitalization

EngD industry project

How can restaurant and customer needs inform an AI ordering assistant—and how can its data support order completion prediction?

0.79 Approximate ROC AUC for order completion prediction

My contribution

Gathered input from four restaurants and 65 customers, translating the findings into 35 prioritized requirements. Built a scheduled Databricks workflow to validate 221 simulated customer sessions.

Session data → Validation → Delta Lake → Prediction
Read about my approach

Checking the data

Checked sessions for missing, duplicate, and invalid records. Stored validated data in Delta Lake and prepared structured datasets for modeling.

Testing the experience

Developed and A/B tested ordering interface variants, using SQL to analyze order completion rates.

Developing the models

Developed Logistic Regression and XGBoost models to predict order completion, achieving approximately 0.79 ROC AUC.

ROC AUC measures how well a model distinguishes completed orders from incomplete orders across classification thresholds. It is not the same as percentage accuracy.

Data context

The validation workflow covered 221 simulated sessions. I also worked with data stewards on responsible handling of customer and restaurant data.

Python · SQL · Azure Databricks · Delta Lake · XGBoost

ENEXIS · 2024

Electricity Forecasting

EngD industry project

Preparing electricity load records and time-based features for infeed and grid loss forecasting.

7.63% MAPE for the GRU forecasting model

My contribution

Developed PySpark processing workflows in Azure Databricks and engineered lag, rolling average, and calendar features for downstream forecasting.

Load records → Transformation → Feature tables → GRU model
Read about my approach

Understanding the requirements

Collaborated with a lead Data Scientist to understand the supplied datasets and clarify business requirements.

Preparing forecasting features

Used PySpark window functions to create lag features, rolling averages, and calendar features. Prepared the resulting data as Databricks feature tables.

Training and results

Used chronological training for a GRU model, achieving 7.63% mean absolute percentage error. MAPE expresses forecast error relative to actual values.

Processing performance

The data processing workflow ran in 1 minute and 2 seconds in the development environment. This is a development runtime, rather than a production benchmark.

PySpark · Azure Databricks · Feature Engineering · GRU
